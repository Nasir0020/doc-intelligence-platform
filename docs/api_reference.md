# API Reference

Base URL: `http://localhost:8000` (local) or your deployed Railway URL.

Interactive docs (Swagger UI, auto-generated by FastAPI) are always available at `/docs` on a running server.

## `GET /health/`

Liveness check. No auth, no parameters.

**Response `200`**
```json
{ "status": "ok", "app_name": "Document Intelligence Platform", "environment": "development" }
```

## `POST /documents/upload`

Uploads and indexes a PDF document.

**Request**: `multipart/form-data` with a single field `file` (PDF only).

**Responses**
| Status | Meaning |
|---|---|
| `201` | Indexed successfully — returns a `DocumentSummary` |
| `400` | Not a PDF file |
| `409` | A document with this filename is already indexed |
| `422` | PDF parsed but yielded no extractable content |

**`201` body**
```json
{
  "filename": "quarterly_report.pdf",
  "total_pages": 12,
  "total_chunks": 34,
  "ocr_pages_used": 2
}
```

## `GET /documents`

Lists every indexed document.

**Response `200`**: array of `DocumentSummary` (same shape as above).

## `POST /query`

Asks a question against all indexed documents.

**Request body**
```json
{ "question": "What was the APAC growth percentage?", "top_k": 5 }
```
- `question` — required, 1–2000 characters
- `top_k` — optional, 1–20, default 5 (how many source chunks inform the final answer)

**Responses**
| Status | Meaning |
|---|---|
| `200` | Success — returns a `GeneratedAnswer` |
| `404` | No documents indexed yet, or no relevant results found |
| `422` | Invalid request body (e.g. empty question) |
| `502` | The upstream LLM call failed |

**`200` body**
```json
{
  "answer_text": "APAC revenue grew 18% this quarter [Source 1].",
  "citations": [
    {
      "source_number": 1,
      "chunk_id": "quarterly_report.pdf_chunk_0007",
      "source_filename": "quarterly_report.pdf",
      "page_numbers": [4]
    }
  ],
  "grounded": true
}
```

`grounded: false` means the model determined the indexed documents don't contain enough information to answer — `citations` will be empty in that case, and `answer_text` explains why.
